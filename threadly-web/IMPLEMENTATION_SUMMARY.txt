ROUTING CONFIGURATION

API Gateway Routes (Nginx :8080):

  /auth/*        → identity-service:3001
  /bots/*        → workspace-service:3002
  /flows/*       → flow-service:3003
  /sessions/*    → runtime-service:3004
  /conversations/* → conversation-service:3005
  /kb/*          → knowledge-service:3006
  /dashboard/*   → analytics-service:3007
  /billing/*     → billing-service:3008
  /integrations/*→ integration-service:3009

Request Flow:

  Browser Request
       ↓
  threadly-web (:3000)
       ↓
  All requests include:
  - Authorization: Bearer {jwt}
  - X-Trace-ID: {32-char-hex}
  - Content-Type: application/json
       ↓
  Nginx Gateway (:8080)
       ↓
  Routes to appropriate microservice
       ↓
  Service handles request
       ↓
  Response with distributed tracing span

FEATURES ENABLED

1. Distributed Tracing (OpenTelemetry)
   • Every request includes X-Trace-ID header
   • Spans all hops: browser → Nginx → service → Kafka
   • Visible in Honeycomb or Tempo
   • Single trace ID per user request

2. JWT Authentication
   • Login: POST /auth/login (returns accessToken + refreshToken)
   • Refresh: POST /auth/refresh (auto-called at 14 min mark)
   • Session: Token stored in Next.js session (JWT strategy)
   • All requests: Authorization: Bearer {token}

3. Zero Service-Direct Calls
   • No hardcoded service URLs in code
   • All requests routed through Nginx
   • Nginx logs show all traffic
   • Single source of truth for API routing

4. Rate Limiting
   • /auth endpoints: 5 requests/min (login attempts)
   • Widget endpoints: 1000 requests/sec (bot conversations)
   • General endpoints: 100 requests/sec (API calls)
   • Enforced at Nginx gateway layer

5. CORS Handling
   • Centralized in Nginx configuration
   • Consistent across all endpoints
   • Handles preflight requests automatically
   • Origin checking at gateway level
