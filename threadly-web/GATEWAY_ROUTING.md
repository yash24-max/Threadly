# Threadly-Web Nginx Gateway Routing

## Architecture Overview

All API calls from threadly-web are routed through the Nginx API Gateway at `http://localhost:8080` (dev) or configured domain (production).

The gateway routes requests to appropriate microservices:
- `/auth/*` → identity-service:3001
- `/bots/*` → workspace-service:3002
- `/flows/*` → flow-service:3003
- `/sessions/*` → runtime-service:3004
- `/conversations/*` → conversation-service:3005
- `/kb/*` → knowledge-service:3006
- `/dashboard/*` → analytics-service:3007
- `/billing/*` → billing-service:3008
- `/integrations/*` → integration-service:3009

## Configuration Files

### Environment Variables
- `.env.local`: `NEXT_PUBLIC_API_URL=http://localhost:8080`
- `.env.production`: `NEXT_PUBLIC_API_URL=https://api.threadly.dev`

### Core API Files

#### 1. `lib/api.ts` — Base HTTP Client
- Reads `process.env.NEXT_PUBLIC_API_URL` (always routes via gateway)
- Injects `Authorization: Bearer {jwt}` header from Auth.js session
- Injects `X-Trace-ID` header for distributed tracing (OpenTelemetry)
- Methods: `get()`, `post()`, `patch()`, `delete()`, `upload()`

#### 2. `lib/api-mutator.ts` — Orval-Generated API Hooks
- Custom mutator for Orval code generation
- Called by auto-generated TanStack Query hooks
- Reads session token from `getSession()`
- Injects same auth + tracing headers as `lib/api.ts`
- Used by: `lib/generated/api.ts` (auto-generated)

#### 3. `auth.ts` — Next.js Auth Configuration
- Credentials provider sends login to `/auth/login` via gateway
- JWT callback validates and refreshes tokens via `/auth/refresh`
- Session callback injects `accessToken` into React session
- Exports: `handlers`, `signIn`, `signOut`, `auth()`

#### 4. `orval.config.ts` — OpenAPI Code Generation
- Fetches OpenAPI schema from `http://localhost:8080/openapi.json`
- Generates TanStack Query hooks in `lib/generated/api.ts`
- Hooks use `api-mutator.ts` for all HTTP calls
- Run: `npm run codegen`

## Key Features

### 1. Distributed Tracing
Every request includes `X-Trace-ID` header:
- Generated by `generateTraceId()` in `api.ts` and `auth.ts`
- Spans all hops: browser → Nginx → microservice → Kafka
- Visible in Honeycomb or OpenTelemetry backend

### 2. JWT Authentication
- Login: `POST /auth/login` → returns `accessToken` + `refreshToken`
- Refresh: `POST /auth/refresh` before token expires (at 14 min mark)
- All subsequent requests include `Authorization: Bearer {jwt}`
- Token stored in Next.js session (not localStorage)

### 3. Realtime Updates (Centrifugo)
- Get JWT token: `GET /realtime/token` (routed via Nginx)
- Token includes `org_id` + `user_id` for Centrifugo validation
- Used by: `app/(app)/conversations/page.tsx`

### 4. API Endpoints (Examples)

#### Workspace Service
```bash
curl -H "Authorization: Bearer $JWT" http://localhost:8080/bots
```

#### Knowledge Base
```bash
curl -H "Authorization: Bearer $JWT" \
  -F "file=@document.pdf" \
  http://localhost:8080/kb/upload
```

#### Analytics
```bash
curl -H "Authorization: Bearer $JWT" http://localhost:8080/dashboard/stats
```

## Usage in Components

### Using `api` object (simple requests)
```typescript
const { data: bots } = useQuery({
  queryKey: ["bots"],
  queryFn: () => api.get("/bots", session?.accessToken),
  enabled: !!session,
});
```

### Using Orval-generated hooks (recommended)
```typescript
import { useGetBots } from "@/lib/generated/api";

export function BotsPage() {
  const { data: bots } = useGetBots();
  // ...
}
```

## Testing

Run tests with gateway running:
```bash
npm test
```

Tests use the same gateway URL:
- Auth tests: `POST /auth/signup`, `POST /auth/login`
- API tests: Direct calls to gateway endpoints

## Development Checklist

Before running locally:
1. Start Nginx gateway: `docker-compose up nginx`
2. Start microservices: `docker-compose up` (all services)
3. Run threadly-web: `npm run dev`
4. Verify gateway health: `curl http://localhost:8080/health`
5. Generate API hooks: `npm run codegen`

## Common Issues

### Issue: 404 on `/openapi.json`
**Solution**: Nginx gateway must have SpringDocs configured (Spring Boot 3.1+)
- Verify gateway forwards `/openapi.json` to a service with SpringDocs
- Alternative: manually configure path if needed

### Issue: Token not found in requests
**Solution**: Check that `getSession()` is called before API request
- Ensure component is inside `<SessionProvider>`
- Use `useSession()` hook to check session availability

### Issue: CORS errors on Centrifugo connection
**Solution**: Token is passed, but Centrifugo must allow CORS
- Verify Centrifugo CORS config allows requests from `http://localhost:3000`
- Token from `/realtime/token` endpoint must match Centrifugo secret
